# AIVA development and test mock chat

MOCK ONLY, loopback, without MySQL, robot hardware, provider keys, Internet Search
or production settings. No `.env` is loaded. Production AppModule never imports
the mock Nest module; production app.main never imports the separate FastAPI app.

## Run from the repository root

Use the Frontend virtualenv interpreter and the separate AI interpreter:

```powershell
D:\aiva-tools\D4-S1-02\frontend-venv\Scripts\python.exe -B tools\mock_chat\run.py --enable --serve --ai-python D:\aiva-tools\D4-S1-02\ai-venv\Scripts\python.exe --output D:\aiva-tools\D4-S1-05-MOCK\logs
```

`--serve` starts real Streamlit, Nest and FastAPI children on free loopback ports,
prints the UI URL and opens no browser. Ctrl+C stops only its own children.
Replace `--serve` with `--smoke` to render real frontend/app.py through AppTest,
using actual TCP HTTP, and check the answer, loading, and AI/BE disconnections.
Smoke exits and closes its processes. Logs/results go to a new directory per run.

Fixture login: `mock-user@example.test` / `MockOnly-Password-2026!`. These are
synthetic fixture credentials, not a real database account. Normal AuthService
verifies bcrypt and issues JWT/refresh sessions in RAM. Normal JwtAuthGuard and
RolesGuard check requests. No demo login or production guard changes.

## Flow

FE uses existing login, /auth/me, AI profile, content-only POST /web-chat/messages,
spinner, response rendering and errors. Layout/menu/theme/robot remain unchanged.
Nest uses real AiController/AiService/AIWebChatClient. A mock-only gateway delegates
HTTP first, then saves the validated result to bounded RAM conversation 11 for
User 7. AiService still checks its owner and assistant message. No retry/fallback.

User 7 owns MOCK robot 42 with APPROVED status. Another owner is rejected. This
is fixture ownership evidence, not real device authorization acceptance.
FastAPI POST /internal/web-chat requires a dedicated service token and body
{userId,content}, allows only fixture User 7 and returns:

```json
{"content":"[MOCK] AIVA fixture response from FastAPI.","conversation_id":"11","usage":{"input_tokens":0,"output_tokens":0}}
```

Actual provider token usage is not claimed. No cloud key is used. A fresh service
token is generated by the launcher and passed only in child environment. Missing
explicit development/test opt-in refuses app construction. Bind is 127.0.0.1.
No payload logging; no DB seed, file persistence or outbound provider calls.
RAM holds only the latest synthetic turn and disappears on exit. Enter test data.

This isolated mock does not implement production quota, history/privacy, Local
routing, credential delivery or TLS, and cannot be a production fallback.

## Targeted checks

In BE: `node node_modules/typescript/bin/tsc --project test/mock-chat/tsconfig.json`,
`npm.cmd run build`, and Jest paths `test/mock-chat/runtime.spec.ts`,
`test/phase1-ai-integration.spec.ts`, `test/live-chat.spec.ts`, `test/ai.service.spec.ts`.
In AI venv/AI_SERVER: pytest `tests/test_mock_chat.py`,
`tests/test_live_gemini_integration.py`, `tests/test_backend_client.py`.
The launcher sets TS_NODE_FILES=true to load existing bcrypt declarations;
typechecking remains enabled and dependency versions do not change.

Mock fixtures, cross-process local mock, browser/manual UI and live provider/DB/
hardware acceptance are separate results. AppTest is not a browser pixel test.
